# Current retrieval baseline

This document freezes the retrieval configuration and evidence used for the
0.9 stabilization window. It distinguishes committed, third-party-reproducible
checks from maintainer-local scale measurements. Private/generated scale
indexes and reports are not release assets.

## Canonical configuration

| Setting | Frozen value |
| --- | --- |
| Record schema | 2 |
| Embedding input | 3 |
| Index format | 3 |
| Profile prompt | 2 |
| Embedding | `nvidia/llama-nemotron-embed-1b-v2`, 2048 dimensions |
| Index views | single `search_text` view |
| Ranking | reciprocal-rank fusion of semantic recall and reranker evidence |
| Reranker | `nvidia/llama-nemotron-rerank-1b-v2` |
| Candidate limit | 50 |
| Query transform | fixed English `canonical` query for evaluation |
| Search threshold | 0.26 |
| Reranker abstain threshold | -8.0 |
| Top-k for evaluation | 10 |
| Confidence calibration | `off` |

The single-view index is canonical because the measured multiview challengers
did not consistently improve dev and holdout retrieval. Fixed canonical query
files make comparisons repeatable and prevent query-transform model drift from
changing a frozen run. Interactive searches may use a live transform endpoint,
but those runs are not directly comparable to this baseline.

## Datasets

`data/scale-cross-domain-dev.json` and
`data/scale-cross-domain-holdout.json` are committed, deterministic 60-case
splits generated by `scripts/generate_cross_domain_eval.py`. Each split covers
five domains, English and Chinese, and exact, functional, ecosystem, ambiguous,
and no-result query families. Dev is the only tuning split. Holdout is reserved
for milestone acceptance.

The generator validates targets against supplied corpora and verifies that
no-result sentinels are absent. Use `scripts/summarize_eval_slices.py` to inspect
every domain/language/category rather than relying only on aggregate metrics.

## Public offline regression

The small fixture under `examples/retrieval-regression/` is committed and fully
reproducible without credentials or network access:

```bash
python scripts/run_retrieval_regression.py
```

It currently contains six cases and protects exact identity, functional,
ecosystem, ambiguous, Chinese, and no-result behavior. Its synthetic 4D vectors
are a search-contract regression fixture, not a quality benchmark.

## Scale evidence

The following table is filled only from reports produced by the named commit
and configuration. Scale reports remain ignored local artifacts; the commands,
configuration and aggregate results are recorded here so claims remain
auditable. Endpoint latency is included in report duration.

| Corpus / split | Cases | Recall@1 | Recall@5 | MRR acceptable | Abstain | Duration | Evidence |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 2k dev | 60 | 53.3% | 73.3% | 0.6350 | 18.3% | 279.5 s | `0.9.0` release run |
| 2k holdout | 60 | 55.0% | 75.0% | 0.6417 | 20.0% | 333.3 s | `0.9.0` release run |
| 10k dev | 60 | 40.0% | 70.0% | 0.5265 | 18.3% | 253.5 s | `0.9.0` release run; 9,989 repos |
| 10k holdout | not run | — | — | — | — | — | deliberately not run after configuration freeze |

The 10k holdout was deliberately not run: the 2k holdout supplies independent acceptance evidence, while 10k dev validates corpus-scale behavior. A future 10k holdout run must use this frozen configuration and must not feed further tuning.

All three release runs reported zero wrong high-confidence top-1 results. The 10k dev Recall@1 is lower than the earlier multiview challenger; this release chooses the reproducible single-view contract and records the gap rather than changing configuration after holdout review.

## Reproduction commands

The local generated index must report the exact model, schema/input versions,
and dimension above. With approved endpoint configuration loaded:

```bash
xists eval run \
  --cases data/scale-cross-domain-dev.json \
  --index /path/to/current-index-v3.json \
  --output /tmp/xists-retrieval-dev.json \
  --top-k 10 \
  --ranking-strategy rerank \
  --rerank-candidates 50 \
  --exploratory-threshold 0.26 \
  --rerank-abstain-threshold -8 \
  --query-transform-mode canonical \
  --canonical-queries examples/retrieval-baseline/canonical-dev.json

python scripts/summarize_eval_slices.py \
  --report /tmp/xists-retrieval-dev.json --format markdown
```

Run the holdout command only after the dev configuration is frozen. Do not
change profile, embedding, metadata weights, transform, reranker, candidate
limit, or thresholds based on holdout misses.

## Known failure classes

- Functional and ecosystem queries can retrieve a broadly related but
  role-incompatible repository.
- Chinese embedding recall is useful, but English-dominant profiles still make
  Chinese queries less reliable than their English pairs. The lightweight CJK
  terms added in 0.9 improve intent, overlap and explanations; they do not
  replace multilingual profile quality.
- Ambiguous queries often have several legitimate alternatives, so exact and
  acceptable metrics must remain separate.
- No-result calibration remains difficult: a semantically adjacent project can
  be returned with excessive confidence.
- Exact `owner/repo` and exact name/alias lookup is reliable; a project name
  embedded in a broader request is contextual evidence and is never pinned.

## Interpretation rules

- `Recall@1`, `Recall@5`, and MRR use dataset-declared acceptable targets.
- No-result abstention and wrong high-confidence counts are release evidence,
  not optional diagnostics.
- Internal 2k/10k numbers must always be labeled internal unless the underlying
  corpus/index is published.
- The public fixture proves deterministic behavior only; it must never be used
  to advertise production retrieval percentages.
